# Go TUI plan

Started 2026-09-20. Amended 2026-09-27: the goal changed from a minimal inline client to a full-screen copy of the Textual TUI.

Status: P0, P1, M0, M1 and M2 merged. F1 in review, F2 built on top of it. Next: F3.

## Goal

A Go terminal client for `voss serve` that looks and behaves exactly like the Textual TUI that bare `voss` opens today (`voss/harness/tui/`), and then replaces it. The Rust client `crates/voss-tui` is frozen and is deleted in F5. The Textual TUI stays the default until R1.

"Exactly" means the Textual TUI as a user sees it: the same screen layout, colours, glyphs, text and keys. The source of truth is the Textual code plus the as-built section of `docs/tui-redesign-spec.md`. Where the two disagree, the code wins.

Done means:

1. Every feature in the parity inventory below is either built or waiting on a named server change.
2. Side-by-side screenshots of both clients on the same session match at 80x24 and 120x40.
3. `VOSS_USE_TUI=1 VOSS_TUI_BIN=<go binary> voss` launches it through the existing dispatcher.
4. The cold pass in "Testing" passes.

## Decisions

| Topic | Decision | Why |
|---|---|---|
| Location | `tui/`, its own module, with `replace github.com/vosslang/voss/sdk/go => ../sdk/go` | Unchanged from the MVP plan. |
| Binary name | `voss-tui-go`, renamed to `voss-tui` when the Rust client is deleted | Unchanged. |
| Libraries | Bubble Tea v2, bubbles v2, lipgloss v2, goldmark and chroma for markdown. `ultraviolet` pinned for the shrink fix. | glamour was replaced by a port of Rich's markdown renderer in F1. |
| Screen mode | Full screen (alt screen) with an in-app scrollable transcript. Supersedes the inline decision. | The Textual TUI is full screen: centred home screen, pinned status line and input. Inline mode cannot match it. |
| Parity rules | Match what a user can reach. Skip Textual behaviour that is unreachable or dead: the "main" keys (`j k ctrl+d ctrl+u g G f ctrl+f`) listed in help but never bound, the footer budget segment (`budget_total` is always 0), the plan-mode input border (phase is never plan), the budget-exhausted modal (nothing opens it), the launch session toast (never fires). | Agreed 2026-09-27. |
| Key conflicts | Textual's keys win. Go-only keys stay where they do not collide. | See "Where the Go client differs today". |
| Extras | Keep the pi-style additions where they do not conflict: Emacs editing keys, Ctrl+G to edit in `$EDITOR`, a persistent prompt history file, the word diff in permission prompts, Ctrl+O. | Agreed 2026-09-27. |
| Server work | Client parity first (F1 to F4). Then each server change ships with the client feature it unlocks (S1 to S9). | Agreed 2026-09-27. |
| Rust client | Frozen now, deleted in F5. | Speed is set by the Python server, not the client language. The Go client is already further along. |
| Textual TUI | Retired in R1, after S1 to S9. | Retiring it earlier loses ambient chat, server slash commands, diff review, the model picker and resume replay, which exist only in the in-process path today. |

## Milestones

Each milestone is one branch and one PR, split into commits by concern. Line counts are estimates.

### F1. Full-screen shell (about 1,500 lines)

| Task | Check |
|---|---|
| Alt screen; transcript as a scrollable viewport of rendered blocks; follow the tail unless scrolled up; new user message re-follows; mouse wheel and PgUp/PgDn scroll | scroll up mid-stream: no jump; send a message: view returns to the bottom |
| `theme.go`: the 9 palette colours and the glyph table with ASCII fallback under `VOSS_NO_UNICODE=1`, copied from `palette.py` and `glyphs.py` | a test pins every value against the Python files |
| Home screen with logo, `v1`, `cwd` + git counts, `model`, `resume`, hint; removed on first block | matches a Textual screenshot of the same repo at 120x40 and at 60 columns (text logo) |
| Status line, two zones, middle truncates first | values match `GET /session/:id/cost` after a turn; bar turns warn at 75% |
| Blocks restyled: user block, assistant gutter + footer, role blocks, working indicator as the last line | golden full-screen snapshots at 80x24 and 120x40 |
| Input bar: border states, `▌` prompt, placeholder, height 3 to 8 | focus change recolours the border |
| Toast overlay, persistent thinking toast | `thinking` shows `⏵ label` until `final` |
| Key changes: Ctrl+C (abort or exit), Shift+Tab focus, Esc no longer aborts | the key table in the help test matches Textual's reachable keys |

F1 as built:

- The transcript is a viewport inside the alternate screen. It follows new output unless the user scrolls up with the wheel or PgUp, and a new user message returns it to the bottom.
- Text wraps at the window width minus 4, measured from the Textual TUI: one column of padding on each side and a two-column scrollbar gutter.
- `theme.go` copies the palette and glyphs; a test parses `palette.py` and `glyphs.py` and fails on drift. Colour blends round down, which reproduces Textual's 6% and 15% tints exactly. Default text is `#e0e0e0`, as measured.
- Markdown goes through `richmd.go`, a port of `rich.markdown.Markdown`, not glamour. `testdata/richmd` holds samples with Rich's own renders, made by `gen.py`; the port matches all of them. Images stay inline, where Rich prints them before the paragraph.
- The Go SDK gained `OpenSession`, which returns the auth source the status line needs.
- `/mode` moved into F1 because Shift+Tab stopped cycling the mode.
- `COLORTERM=truecolor` is trusted under tmux, as Rich does, so colours match there.
- Checked side by side with the Textual TUI in tmux: home screen identical at 80 and 110 columns apart from the model; status line, input bar and user block identical escape for escape; markdown sample differs in four blank cells.
- Found while checking: `voss serve` ignores `[harness] auth` from `~/.config/voss/config.toml`, which the CLI honours, so the two clients can pick different providers. Server fix to follow.

### F2. Input, modals and slash (about 1,300 lines)

| Task | Check |
|---|---|
| Permission and scope modals with Textual's wording; word diff inside the edit modal. The scope modal gains `[a] always (this session)`, which must reply `always`: the server's scope check accepts `y`/`once` and `always`, and treats anything else, including `a`, as a denial. | wording matches `permission_modal.py` exactly; `[Esc]` denies; scope `a` stops later scope prompts |
| Queued chips; paste chip; Ctrl+R reverse search | queue 3 messages mid-turn, they send in order; Ctrl+C clears them |
| `@` file palette; `!cmd` with the sandbox allow-list; `#note` | `!rm -rf x` is refused as Textual refuses it |
| Slash palette over client-served commands, ranked like `slash_palette.py`; unknown commands print `unknown command: X. /help for list.` | each served command works; others are not sent as prompts |
| Help overlay, Ctrl+Y copy, Ctrl+L redraw, transcript nav mode | nav keys work only when idle |
| Trim policy | a 600-block session keeps 400 plus the placeholder |

F2 as built:

- Permission and scope prompts replace the whole screen, as Textual's modal screens do, with the verb and target rules from `permissions_bridge.py`. Textual renders the key lines as markup, which drops `[a]` and `[d]`; the Go client shows the intended text. That Textual bug is a one-line fix (`markup=False`) worth making separately.
- The scope modal gained `a`, which replies `always`.
- Everything entered during a turn queues, slash commands included, and replays in order through one dispatch path. The queue chip matches `#queued-chips`.
- Paste chips and Ctrl+R follow `input_bar.py`. Ctrl+R searches the session's own messages; the history file is F4.
- `!cmd` and `#note` run at once, even mid-turn. `testdata/local` holds Python's own results for `shell_allowed`, `shlex.split` and the VOSS.md note append; the Go port matches them byte for byte.
- The slash and `@` palettes rank like Textual's. Textual's palette overlaps the input border and hides the status line; the Go palette sits above the input. It lists only the commands this client runs: `/help`, `/exit`/`/quit`, `/mode`, `/cost`, `/diff`, `/doctor`, with the CLI's help text and output. `/doctor` lacks the CLI's "machine-repairable" line because the server does not send repair data.
- Nav mode, Ctrl+Y, timed toasts and the 500-block trim follow `turn_view.py`. The help overlay is skipped: Textual's text area swallows `?`, so users cannot reach it.
- `/resume`, `/memory` and `/recall` moved to F5 with resume.

## Testing

- Reducer, diff and chat-driver tests carry over from M1 and M2.
- Full-screen snapshots: render `View()` at 80x24 and 120x40 for the home screen, a finished turn, a running turn, each modal and each palette. Golden files store text with styling stripped. A test fails if any line is wider than the screen.
- Parity check per milestone: run both clients on the same repo and session, capture both with tmux at the same size, and compare. Differences are either fixed or listed in the PR.
- Integration against `VOSS_SERVE_FAKE_TURN=1` through `VOSS_BIN`; skipped when no executable resolves, as in CI.
- Cold pass before F5: new project with no `.voss/`, 60-column window with a resize mid-stream, tmux, iTerm2, Ghostty, a Voss-ADE pane (xterm.js), quit mid-stream then `resume`, a permission prompt in every mode, `pgrep` for leftover servers.

## Risks

- **Alt screen hides the terminal's own scrollback.** Users scroll inside the app, as in Textual. Copying long output needs Ctrl+Y or nav-mode `y`.
- **Mouse capture** for wheel scrolling can interfere with terminal text selection. Textual has the same trade-off; match its behaviour.
- **xterm.js in Voss-ADE** may not support every sequence. Test F1 inside an ADE pane before F2.
- **ADE agent detection** looks for the Python process. A Go process needs a detector entry in Voss-ADE.
- **Two clients drift.** Any Textual change after F1 needs a matching Go change. The snapshot comparison catches drift.
- **S1 gate.** If the tool event contract stays frozen, F3's client-side cards are the ceiling.
