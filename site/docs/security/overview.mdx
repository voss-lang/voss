title: "Security model"
description: "How Voss constrains local agent work through modes, scope, prompts, and session redaction."
---

Voss is local-first and repo-scoped. The security model is built around explicit boundaries.

## Boundaries

| Boundary | Purpose |
| --- | --- |
| Permission modes | Separate read-only planning from editing and automation |
| Cwd jail | Keep file access rooted in the selected repository |
| Edit scope | Limit writes during `voss edit` |
| Tool classification | Distinguish read-only and mutating tools |
| Diff preview | Show file changes before risky approvals |
| Shell allowlist | Limit command execution |
| Session redaction | Avoid storing provider credentials |
| Project memory | Keep `VOSS.md` and `.voss/memory` local to the repo |
| Permission prompts | Route permission and scope decisions through explicit review screens in the Go client and `voss chat` |
| Network default-deny | Keep web and MCP tools off unless `--allow-net` or `[tools] allow_net` enables them |
| Loopback server | `voss serve` binds to `127.0.0.1` and requires a per-process bearer token |

## Scoped writes

`voss edit` grants write access only to explicit targets and relevant existing tests. Other writes require approval after a diff preview.

## Shell execution

Shell execution is mutating and potentially risky. It is denied in edit mode and remains subject to lower-level allowlist behavior in broader modes.

## Managed execution

When Voss ADE launches its engine, `voss serve` runs in OAuth-only mode: managed sessions and swarms accept subscription OAuth only, never API keys, and every role is checked before anything is persisted. Child Claude and Codex processes get isolated, temporary login files that are removed when they exit, and conflicting billing variables are stripped. No credential material appears in availability data or task events.

## Secrets

Voss sessions must not store provider credentials or API keys. The Jev key used for judgments is never exported to agent-run child processes, and judgment receipts store IDs, labels, probabilities, and digests, not your criteria, diffs, or code.

<Warning>
Do not paste secrets into prompts. Treat user-provided prompt text as session content.
</Warning>

## Trust goal

The goal is not to make AI work risk-free. The goal is to make risk visible, bounded, and reviewable before it changes your repo.
